Purpose, outcome and scope
ProcureMind AI demonstrates business AI engineering through document intelligence, multi-agent workflow orchestration, deterministic decision logic and human approval. It is not a chatbot. It is a traceable workflow application in which each agent has a defined contract, uses evidence and stores its outputs.
Target final outcome: A user can create an RFQ, add three vendors, upload quotations and a contract, extract structured commercial terms, run the analysis, compare vendors, inspect evidence, approve or override the recommendation and generate a final report.
MVP success criteria
Runs locally on the specified Windows 11 laptop without paid APIs.
Processes at least three digital-text PDF quotations and one contract.
Produces structured extraction with page-level evidence references.
Calculates a reproducible weighted vendor score outside the LLM.
Preserves every agent run, prompt version, evidence set and output.
Requires a procurement manager action before the recommendation becomes final.
Includes automated tests, sample data, architecture diagrams, screenshots and a short demo video.

2.  Analyst selects or creates vendors and uploads each quotation plus relevant contract/compliance documents.
3.  Document service extracts text, chunks content, creates embeddings and stores page metadata.

Concept catalogue with justifications
Concept: Multi-agent orchestration
Meaning
A workflow in which specialized nodes perform bounded responsibilities and communicate through shared state.
How it is used
LangGraph nodes represent supervisor, vendor, quotation, contract, risk and report responsibilities.
Why this method is selected
Specialization makes outputs testable and explainable. A graph also supports retries, branches and human review better than one long prompt.
Trade-off / alternative
A single prompt is faster to prototype but becomes difficult to test, observe and revise.

Concept: State graph
Meaning
A directed workflow made of state, nodes and edges.
How it is used
The RFQ analysis state carries IDs, extracted facts, evidence, agent outputs, errors and approval status.
Why this method is selected
Explicit state prevents hidden data passing and makes each transition inspectable. LangGraph specifically models workflows through state, nodes and edges [R2].
Trade-off / alternative
A sequence of ordinary functions is simpler, but conditional re-analysis and approval loops become harder to maintain.

Concept: Supervisor pattern
Meaning
A coordinator selects and sequences specialist work without doing every analysis itself.
How it is used
The supervisor validates prerequisites, creates the analysis plan and decides whether missing data requires a stop or re-analysis.
Why this method is selected
It centralizes workflow policy while keeping domain prompts small.
Trade-off / alternative
Uncontrolled agent-to-agent delegation can be more flexible but less predictable and more expensive.

Concept: Fan-out / fan-in
Meaning
Independent tasks branch from one state and later merge.
How it is used
Vendor history, quotation comparison and contract analysis can be independent before risk aggregation.
Why this method is selected
It reflects real separation of concerns. On the laptop, logical parallelism can execute sequentially to control GPU memory.
Trade-off / alternative
True concurrent calls reduce latency on a server but can overload a small laptop GPU.

Concept: Structured output
Meaning
The LLM must return a validated schema rather than unrestricted prose.
How it is used
Pydantic models define extracted terms, findings, risks, evidence and confidence.
Why this method is selected
Validation catches missing fields and enables direct storage, scoring and UI rendering.
Trade-off / alternative
Free-form prose is easier to generate but unreliable for downstream automation.

Concept: Retrieval-Augmented Generation (RAG)
Meaning
Relevant document chunks are retrieved and supplied to the model at answer time.
How it is used
Contract and quotation clauses are embedded in pgvector and retrieved by question and document filters.
Why this method is selected
RAG grounds findings in uploaded documents and avoids sending entire PDFs into a small model context.
Trade-off / alternative
Fine-tuning is unnecessary for project-specific documents and requires more data and compute.

Concept: Embeddings
Meaning
Dense numerical vectors represent semantic meaning for similarity search.
How it is used
nomic-embed-text creates local document and query vectors stored by pgvector.
Why this method is selected
A small Apache-licensed embedding model runs locally and separates retrieval from the generation model.
Trade-off / alternative
Keyword search is useful as a hybrid fallback but misses paraphrased clauses.

Concept: Deterministic scoring
Meaning
A fixed mathematical function calculates the final numeric score.
How it is used
Normalized price, delivery, performance, compliance and contract-risk values are combined with user-defined weights.
Why this method is selected
The LLM explains and extracts; deterministic code calculates. This prevents arithmetic drift and improves auditability.
Trade-off / alternative
LLM-only scoring appears intelligent but can change between runs and cannot be independently verified.

Concept: Human-in-the-loop (HITL)
Meaning
A person reviews and authorizes a consequential action.
How it is used
The manager approves, rejects or overrides the recommendation, and the workflow can resume after the decision.
Why this method is selected
Procurement decisions have financial and legal consequences. LangGraph highlights human oversight as a core workflow capability [R1].
Trade-off / alternative
Autonomous selection is inappropriate for an interview MVP and weakens accountability.

Concept: Evidence provenance
Meaning
Every claim records where its support came from.
How it is used
Findings store document ID, page number, chunk ID and a short supporting excerpt.
Why this method is selected
Provenance allows reviewers to verify the recommendation and is essential for trustworthy document AI.
Trade-off / alternative
A simple answer without citations is faster but cannot be audited.

Concept: Confidence calibration
Meaning
The system distinguishes confidence from truth.
How it is used
Agents return high/medium/low confidence with missing-information reasons.
Why this method is selected
This encourages conservative behavior when documents are incomplete.
Trade-off / alternative
A numeric probability would look precise but is not statistically calibrated in this MVP.

Concept: Idempotency
Meaning
Repeating an operation does not create duplicate business effects.
How it is used
Document hashes prevent duplicate ingestion; analysis run IDs prevent duplicate approvals and reports.
Why this method is selected
Retries are common in AI workflows. Idempotency makes failure recovery safe.
Trade-off / alternative
Without it, a retry can duplicate chunks, reports or audit events.

Concept: Audit trail
Meaning
Immutable records show who did what and when.
How it is used
Activity logs capture uploads, analysis starts, agent versions, decisions and overrides.
Why this method is selected
It demonstrates enterprise governance and supports interview questions about accountability.
Trade-off / alternative
Only application console logs are insufficient because they are not tied to business entities.

Concept: Local inference
Meaning
Models run on the user's device rather than a paid API.
How it is used
Ollama serves Qwen3 4B and nomic-embed-text on Windows.
Why this method is selected
It satisfies zero-cost operation, keeps sample documents local and demonstrates model-provider abstraction.
Trade-off / alternative
Hosted models may produce better answers but introduce cost, keys and network dependency.

System and agent architecture

ProcureMind AI logical system architecture
Architecture justification
Modular monolith: One FastAPI service is selected instead of microservices because it is faster to build, debug and run on a laptop. Internal packages preserve boundaries so services can be separated later.
Relational plus vector database: PostgreSQL stores business transactions and pgvector stores embeddings in the same database. This reduces operational complexity and allows metadata joins during retrieval.
Native Ollama: GPU inference runs directly on Windows while the database runs in Docker. This avoids GPU passthrough configuration and keeps the deployment understandable.
Local filesystem: Uploads and generated reports use a controlled storage directory for the MVP. A storage interface allows S3 replacement later.
REST API: REST is selected because CRUD, uploads and status polling are easy to demonstrate through Swagger and React. GraphQL is unnecessary for this bounded MVP.

Document intelligence and RAG pipeline

Document ingestion and evidence-grounded retrieval pipeline
Processing steps
1.  Validate extension, MIME type, size and cryptographic hash.
2.  Extract text page-by-page using pypdf. Record extraction quality metrics.
3.  When a page contains almost no text, mark it OCR_REQUIRED. Tesseract can be added as a free optional path.
4.  Normalize whitespace but preserve page boundaries and headings.
5.  Chunk primarily by headings/clauses, falling back to approximately 500-800 tokens with 80-token overlap.
6.  Generate embeddings locally and store vector, document ID, page range, section and text hash.
7.  At query time filter by RFQ, vendor and document type before semantic ranking.
8.  Retrieve a small evidence packet and require structured citations in the agent output.
9.  Validate every cited chunk belongs to the current RFQ and document.
10.  Persist extraction and retrieval metrics for debugging.
Why section-aware chunking is used
Contracts are organized by clauses, definitions and schedules. Fixed-size chunks can split a condition from its exception. The pipeline first tries headings and paragraph boundaries, then enforces a maximum token size. This is more explainable than blindly splitting every N characters.
Hybrid retrieval option
For the first version, use cosine similarity plus metadata filters. Add PostgreSQL full-text search only if queries based on exact clause numbers, vendor codes or rare terms perform poorly. A weighted hybrid rank is a future improvement, not a Day 2 requirement.

Scoring method
A score from 0 to 100 is calculated for each vendor. User-editable weights must sum to 100. The LLM never performs the final arithmetic.
# Example weightsprice_weight       = 30quality_weight     = 20delivery_weight    = 20compliance_weight  = 15contract_weight    = 15# Lower price is better. Guard against zero and outliers.price_score = 100 * min_valid_price / vendor_price# Lower delivery days is better.delivery_score = 100 * min_delivery_days / vendor_delivery_days# Existing indicators are normalized to 0-100.quality_score = historical_quality_ratingcompliance_score = 100 if compliant else 40 if conditional else 0contract_score = 100 - weighted_contract_risk_penaltytotal_score = (    price_score * 0.30 +    quality_score * 0.20 +    delivery_score * 0.20 +    compliance_score * 0.15 +    contract_score * 0.15)
Important scoring safeguard: A vendor with a mandatory compliance failure is marked ineligible even if its numeric total is high. Hard constraints are evaluated before weighted ranking.

Laptop performance configuration
Ollama concurrency: Run one agent LLM call at a time initially. Parallel graph nodes can be retained logically but executed sequentially on the laptop.
Context size: Use 4K context by default. Retrieve only the top 4-6 chunks and summarize long documents before the final synthesis.
Embedding batch: Embed 16-32 chunks per batch. Persist embeddings so documents are not reprocessed on every run.
Database: Use HNSW only after data exceeds a few thousand chunks. Exact search is adequate for small sample data.
Frontend: Disable unnecessary animated charts during model execution. Poll agent-run status every two seconds rather than using WebSockets in the MVP.
Thermal stability: Use AC power and the Windows best-performance power profile for demo recordings.

Workflow routing rules
If required documents are unprocessed, stop with NEEDS_INPUT.
If currencies differ and no conversion policy exists, stop quotation scoring.
If a vendor is ineligible, keep it in comparison but exclude it from recommendation ranking.
If an agent returns invalid structured output, retry once with validation feedback.
If the second attempt fails, store the error and require manual review rather than silently continuing.
After recommendation generation, interrupt the graph until the manager decision is recorded.
On override, preserve both AI recommendation and final human decision.

Why prompts are versioned
Store prompt_name and prompt_version with each agent output. When results change, you can identify whether the model, evidence or instructions changed. This is an important enterprise-AI governance concept and an excellent interview discussion point.

Interview explanation guide
The project becomes valuable only when you can defend its design. Use these answers as a framework, not as memorized marketing language.
Why LangGraph instead of a normal chain?
The workflow contains conditional validation, specialized nodes, stored state, retries and a pause for human approval. A graph expresses these transitions explicitly. A simple chain is adequate for linear summarization but becomes fragile when the process must stop, branch, resume and preserve state.
Why PostgreSQL and pgvector together?
The application has strongly relational RFQs, vendors, submissions, approvals and audit events. PostgreSQL is the natural source of truth. pgvector adds semantic retrieval without operating a second database, and metadata filters can join directly to the relational entities.
Why not let the LLM choose the vendor?
The LLM is useful for extracting and explaining unstructured terms, but a procurement score must be reproducible. Deterministic code performs normalization, eligibility checks and arithmetic. The manager remains accountable for the final decision.
Why use local models?
The project has a zero-cost requirement and includes potentially sensitive documents. Local Ollama removes API charges and external data transfer. The model provider is behind an interface, so a stronger hosted model could be added later without redesigning the workflow.
What is the main limitation?
A 4B local model is weaker than top hosted models and arbitrary PDFs are difficult. The MVP compensates with narrow prompts, structured schemas, small evidence packets, deterministic calculations and carefully prepared test documents.
One-minute project summary
ProcureMind AI is a local multi-agent procurement decision-support platform. Users create an RFQ, upload quotations and contracts, and run an evidence-grounded analysis. LangGraph coordinates specialized extraction and risk agents, while PostgreSQL stores transactional data and pgvector retrieves supporting clauses. A deterministic weighted score prevents the LLM from making an untraceable vendor decision, and a manager must approve or override the recommendation. The complete MVP runs locally using Ollama, so no paid API or cloud dependency is required.
